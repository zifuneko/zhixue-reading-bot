# 智学网「文章朗读」自动完成脚本

在 **安卓模拟器** 里自动完成智学网学生端的「文章朗读」作业：

读取当前段落文字 → edge-tts 合成朗读语音 → 经虚拟声卡送进模拟器麦克风 → 自动开始/结束录音 → 点「确定」进入下一段 → …… → 停在交卷页。

> 智学网网页端不支持朗读录音，必须在安卓环境内完成，所以本项目走「模拟器 + 虚拟声卡」链路。

---

## 一、工作原理

```
                     edge-tts 合成中文语音
┌──────────────┐ ─────────────────────────► tmp_seg.mp3
│  auto_read.py │
└──────┬───────┘
       │ uiautomator2 读界面 / 点按钮
       ▼
  安卓模拟器（智学网学生端）              Windows 音频
  ┌──────────────────────────┐      ┌───────────────────────────┐
  │ 1. 点麦克风 → 开始录音     │ ◄─── │ CABLE Output（录音设备）    │
  │ 2. 波形跟随 → 停止录音     │      │        ▲                  │
  │ 3. 点确定 → 下一段         │      │        │ VB-CABLE 虚拟线    │
  └──────────────────────────┘      │ CABLE Input（播放设备）◄───┘
                                     └───────────────────────────┘
                                          sounddevice 播放
```

关键前提：**模拟器的麦克风必须显式指向 `CABLE Output`**，否则 App 录到的是一段静音，会一直提示「请正常朗读」。

## 二、环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 |
| Python | 3.9 及以上 |
| 模拟器 | MuMu 12 / 雷电 9 等，需开启 ADB，镜像带录音能力（实测 Android 12 可用） |
| 虚拟声卡 | VB-Audio Virtual Cable |
| 网络 | 可访问微软 edge-tts 服务 |

## 三、安装步骤

### 1. 安装 Python 依赖

```bash
pip install -r requirements.txt
```

### 2. 安装虚拟声卡

1. 从 [vb-audio.com/Cable](https://vb-audio.com/Cable/) 下载 VB-CABLE，右键 `VBCABLE_Setup_x64.exe` → **以管理员身份运行** → Install；
2. **重启电脑**（不重启设备不会出现）；
3. 安装后在声音设备里会多出两个：

| 设备名 | 类型 | 用途 |
| --- | --- | --- |
| `CABLE Input (VB-Audio Virtual Cable)` | 播放 | 脚本往这里灌朗读声音 |
| `CABLE Output (VB-Audio Virtual Cable)` | 录音 | 模拟器从这里取声音 |

不用把它设成系统默认播放设备。

### 3. 模拟器设置

1. **开启 ADB**：MuMu 12 在「设置 → 其他 → ADB 调试」打开；雷电默认端口 `5555`。
2. **确认 adb 地址**：MuMu 12 常见为 `127.0.0.1:16416`（不同实例端口不同），用 `adb devices` 查看实际值。
3. **把麦克风指向虚拟声卡**（最关键的一步）：
   - 优先：模拟器「设置 → 音频 → 麦克风设备」选择 `CABLE Output (VB-Audio Virtual Cable)`，保存后按提示重启模拟器；
   - 若模拟器没有该选项：Windows「设置 → 系统 → 声音 → 输入」，把默认输入设备设为 `CABLE Output`，模拟器会跟随系统。**用完记得改回真实麦克风**。
4. 安装并登录智学网学生端，进入作业 → 「文章朗读」，停在**第 1 段的录音页**。

### 4. 环境自检

```bash
python check_env.py --serial 127.0.0.1:16416
```

逐项输出 `[通过] / [失败] / [注意]`，失败项会直接给出修复建议。看到「环境就绪」再往下走。

## 四、运行

```bash
# ① 先只录当前这一段，验证链路（不会提交）
python auto_read.py --mode one

# ② 单段通过后，从当前段一路做到最后，停在交卷页
python auto_read.py --mode full

# ③ 需要脚本自动点「提交作业」时
python auto_read.py --mode full --submit
```

建议顺序：先 `--mode one` 确认这一段能拿到「优秀/良好」，再跑 `--mode full`。

### 常用参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--mode` | `one` | `one` 只录当前段；`full` 录到最后 |
| `--serial` | `127.0.0.1:16416` | 模拟器 adb 地址 |
| `--voice` | `zh-CN-YunjianNeural` | 音色。男声还可用 `zh-CN-YunxiNeural`、`zh-CN-YunyangNeural`；女声 `zh-CN-XiaoxiaoNeural`、`zh-CN-XiaoyiNeural` |
| `--rate` | `-5%` | 语速，略慢更像真人朗读；想快用 `+5%` |
| `--gain` | `1.0` | 音量增益，评分偏低/录音偏小时可调到 `1.2 ~ 1.6` |
| `--device` | 自动 | 手动指定输出设备编号（`python -m sounddevice` 可列出全部设备） |
| `--submit` | 关闭 | 录完后自动点「提交作业」 |
| `--max-segments` | `0` | 最多录几段后停下，`0` 为不限，便于分段试跑 |

示例：

```bash
python auto_read.py --mode full --voice zh-CN-YunyangNeural --gain 1.3
python auto_read.py --mode full --serial 127.0.0.1:5555 --max-segments 5
```

### 脚本行为细节

- **读哪段**：以页面上的段号（`text_index`，形如 `1/17段`）为准，再取出该录音卡片内的 `text_content` 作为朗读文本。所以换文章、段数变化都不需要改代码。
- **不用等示范音**：点录音键后，脚本会轮询直到波纹布局 `layout_recording` 出现（首次点击被示范音挡住时会再点一次），随即播放语音，不等示范播完。
- **怎么停**：点击波纹布局本身结束录音（这是 App 认的停止入口，点麦克风图标是无效的）。
- **怎么推进**：录完若页面已自动跳段则直接继续；若需要点「确定」（`tv_next_question`）则自动点，并等段号 +1。
- **断点续跑**：已经有录音的段（「确定」按钮可用）会自动跳过，中途断掉直接重跑 `--mode full` 即可。
- **收尾**：最后一段完成会截图 `shots/finish_page.png`；不加 `--submit` 就停在这里等你人工确认。

## 五、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 录音后一直提示「请正常朗读」 | 模拟器麦克风没指到 `CABLE Output`，或模拟器工具栏的麦克风开关是关的 |
| 录音时波形是一条直线 | 同上；先用系统「录音机」App 试录一段确认能收到声音 |
| `点录音键后没有进入录音状态` | App 版本改了控件 id；先 `--mode one`，看 `shots/one_seg.png` 再对照修改 `auto_read.py` |
| 点「确定」后段号不动 | 停止入口不对，确认点的是波纹区域；或存在弹窗挡住，看截图 |
| 评分总是「良好」 | `--gain 1.3` 提高音量；`--rate -10%` 放慢一点 |
| `edge-tts` 报错 / 超时 | 网络访问不了微软 TTS，换网络或挂代理 |
| `device not online` | 模拟器没启动或 ADB 未开；`adb connect <地址>` 后重试 |
| 换模拟器实例后连不上 | 端口变了，用 `--serial` 指定 |

## 六、已知限制

- 仅适配 `com.iflytek.elpmobile.student` 的**文章朗读**页面结构，控件 id 是写死的，App 大版本更新后可能失效；
- 一次只能跑一个模拟器实例，不支持并发；
- 只针对模拟器链路；真机需要把音频回灌到手机麦克风，方案不同；
- 语音是合成音，评测系统偶尔会给「良好」而非「优秀」，属正常波动。
